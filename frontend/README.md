# 开放工作台正文保存与恢复

正文保存仍通过本机 Mapping API 和 SQLite。停止输入 400ms 后保存，连续输入最多等待 2s；未结束的 IME 组合不拆分。正文编辑动作以 1s 间隔及选区、输入类型、粘贴、格式、焦点和切卡边界分组，保存批次不等同于撤销步骤。当前入口使用单文本块；完整多块编辑界面由后续正文工单扩展，离开当前编辑区先结束组并提交原卡。

`draft-recovery.ts` 把未确认草稿、结束的动作组和未知结果的原请求保存在浏览器本机 `localStorage`，以编辑会话、项目、卡片隔离。它不是权威正文库，也不进入 40 步操作历史。恢复依赖同一浏览器资料和同一服务源地址；清除浏览器存储、切换资料或端口不会自动迁移这些记录，不承诺崩溃前最后一次按键必定落盘。浏览器容量不足时保留内存输入并明确显示恢复失败。

重开只展示恢复入口，不自动写入。明确恢复先向受鉴权的 `/api/mapping/projects/:id/cards/:cardId/identity` 查询原身份，再以原版本提交。损坏条目保留原文并隔离；已删除身份不能直接恢复正文，撤销删除仍检查绑定动作。旧 ACK 只确认所覆盖 generation；未知结果保留原 commandId、expected 和请求；明确校验拒绝后允许修正并提交最新草稿。

冲突同时展示本机与已保存内容，选择时再次核对远端版本，并先持久保存另一份可恢复副本；副本写入失败就停止选择。之后的写入仍受服务端版本校验，不能用重读结果静默覆盖并发修改。

`body.edit.payload.requiredAssetIds` 是媒体保存门槛。当前 Mapping 尚无已验证的媒体持久化通道，非空引用返回 `MEDIA_NOT_PERSISTED`，不写版本、历史或保存回执。#16 接入真实资源后扩展该门槛及媒体界面；这里没有模拟“已保存”资源。

测试使用随机回环端口、自有临时 SQLite 和全新浏览器上下文；合成 composition、格式及粘贴事件只验证事件协调，不代表真实系统输入法、富文本编辑或系统剪贴板验收。
