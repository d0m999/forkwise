## 01　用户画像（待本人确认，不引用调研数据）

| 项目 | 描述 |
| --- | --- |
| 角色 | 研究者本人。唯一使用者，也是唯一决策者 |
| 背景 | 长期跟踪少量标的与少数作者观点；手上有自有或已授权的语料（X 归档、自存文本、可公开读取的官方披露） |
| 核心目标 | 在作出判断前后，能把「我信哪条、依赖什么、依据在哪、最近什么变了」说清楚，并且是在改动之后仍然说得清楚 |
| 使用场景 | 桌面端本机 Web（Chrome／Safari／Firefox 最新两个版本为兼容性建议目标，D29）；一次研究可能跨数分钟到数周，材料更新是手动触发的离散事件 |
| 典型痛点 | 分散材料里的理由、证据与隐含前提混在一起；分不清哪些是作者表达、哪些是 AI 推断、哪些是自己的推导；新材料进入后找不到受影响的局部；隔几周回看时不知道当时为何这样判断 |
| 能力水平 | 熟练。不需要教学式交互，需要的是可直接操作的研究空间与明确的边界提示（2026-10-01 的易用性反馈：「像在按剧本点下一步」应当被避免） |
| 明确不追求 | 自动生成结论、自动推荐、自动更新、自动排名 |

**次要角色**：无。首版不存在「同事」「订阅者」「管理员」；「AI」在本文中按提出候选意见的非人来源处理，与主张的提出者归属绑定（D07、CONTEXT.md「AI 推断」）。

## 02　用户旅程（一次研究从开始到持续跟踪）

| 阶段 | 本人目标 | 主要行为 | 主要接触点 | 风险／机会点 |
| --- | --- | --- | --- | --- |
| 进入 | 把脑子里的问题与手上的材料放进来 | 新建研究、写下研究问题、粘贴观点或导入材料 | 项目概览 → 研究工作台画布中央输入区 | 风险：误以为要经过「先整理好材料」的门槛。机会：允许空手起步，已有想法先写主张（D53） |
| 得到候选 | 先看系统整理出什么，不急着认同 | 提交后等待重建与公开查证，看候选链、归属标签、查证摘要 | 画布内的候选链、研究卡、任务进度提示 | 风险：候选被当成本人已有判断。机会：默认「待研究」，归属与待核对标记直接贴在卡上 |
| 核对与收录 | 只认真看要用的那部分 | 选择准备收录的链条，逐项核对前提与推导与原文，必要时先看证据 | 对象详情浮窗、材料浮窗、原文锚点定位 | 风险：核对过等于认可（两条状态须分开，D15）。机会：未核对内容可先收录为个人研究草稿（D21） |
| 自己整理 | 改成自己的话、接上自己的推导 | 拖放建立下一步、就地改写、新建主张、删除、调整结构 | 主画布拖放与双击改写、自由绘图批注 | 风险：看不出自己在改什么版本。机会：每次改写要填理由，版本与原版对照可回看（D58、G04） |
| 表态 | 说清自己认什么、疑什么 | 分别给主张与整步推导标注立场与理由 | 研究卡立场区、推导窄条 | 风险：只给结论不给理由，回看时失效。机会：质疑／不认可必须填理由（D38） |
| 假设与分支 | 探不同条件下的情景 | 临时假设预览、保存个人条件路径、并排比较 | 临时假设预览面板、条件路径、比较浮窗 | 风险：把假设预览当成已确认结论。机会：退出即还原，保存才落盘（D46） |
| 跟进 | 新材料来了，知道要看哪里 | 手动导入新材料，看影响建议与受影响局部，三选一复核 | 材料浮窗导入、更新收件箱、对象详情的「需复核」标记 | 风险：新数据自动改写旧判断。机会：需复核标记与原立场分开（D17） |
| 回看与留存 | 隔一段时间还能解释当时为什么 | 主动「记录这次判断」、回看历史判断、导出 JSON 与 Markdown 摘要 | 历史浮窗、设置与用量页 | 风险：只回看到最新版本。机会：回放默认用当时的材料与版本（D28、ADR 0009） |

## 03　用户故事地图

布局约定：**活动 → 任务 → 用户故事（US-xx）**。优先级用 MoSCoW；首个真实案例（`@ShanghaoJin` × `INTC`，D08、D10）跑不通即为 Must。所有故事默认角色为「研究者本人」，故在正文中省略角色句以避免重复，格式改为「我想要……，以便……」。

### 活动 A　建立研究与放入材料

**任务 A1　开工**
| ID | 我想要…… | 依据 | 优先级 |
| --- | --- | --- | --- |
| US-01 | 新建研究后直接进入画布并在中央写下研究问题、粘贴观点或导入材料，以便不用先整理成文档就能开工 | D59、G01 | Must |

**US-01　直接在画布中央开始一项研究**（来源：D59、G01；Must）
作为研究者，我想要新建研究后立刻落在画布中央并写下研究问题、粘贴观点或导入材料，以便不用先经过独立的导入页或先整理好材料。
- Given 我在项目概览点「新建研究」，When 进入工作台，Then 落点是主画布，画布中央出现一个可直接输入的区域（研究问题／观点正文／材料导入），输入区不占用常驻侧栏。
- Given 我已在中央输入区写下内容但尚未提交，When 我离开又回来（同一次会话内），Then 未提交内容保留为草稿，提交后才消耗任务。
- Given 我还没有任何材料，When 我直接写一条自己的主张，Then 系统保存该主张，之后生成的候选链不覆盖它。
- Given 我在画布上的其他位置操作，When 我再次点到中央输入区，Then 已有输入仍可编辑，不因选中别的对象而丢失。

**任务 A2　导入材料与更新入口**
| ID | 我想要…… | 依据 | 优先级 |
| --- | --- | --- | --- |
| US-02 | 在导入前看到这批材料的数量、大小、时间跨度、支持格式与预计处理量，逐个文件看到成功／失败／跳过原因，以便我能部分继续而不必整批重来 | I01、D14、D34 | Must |
| US-03 | 手动导入一份新材料触发更新，并在导入前看到本次会匹配的目标节点范围与预计额度，以便我知道这次更新的边界 | M01、ADR 0008 | Must |
| US-04 | 自己设定目标时间范围，并与实际材料覆盖分开查看，以便我知道哪些是缺的材料而不是缺的观点 | G01、D13、OD-01 | Must |
| US-05 | 看到任务的排队／运行／部分完成／成功／失败／取消状态与实际用量、费用，以便长任务可理解、可取消、可重试 | N01、N02、D33 | Must |

**US-02　有边界地批量导入材料**（来源：I01、D14、D34；Must）
- Given 我选择一批自有材料（文本、文本型 PDF、截图、扫描版 PDF）或已明确有权访问的链接，When 在导入前查看处理提示，Then 显示数量、大小、时间跨度、支持格式与预计处理量。
- Given 一批材料中有 2 份失败、1 份跳过，When 导入结束，Then 按文件分别列出成功／失败／跳过原因，成功部分可继续研究，我不必重新整批导入。
- Given 一条链接直接访问返回 403 或需要登录，When 我尝试导入，Then 标记为受限访问并给出失败原因，不生成证据记录，不用第三方索引内容冒充原文。
- Given 一个多页扫描件只成功识别部分页面，When 查看结果，Then 显示实际成功与失败的页，保留原图与成功内容，不把部分识别计作完整读取。

**US-03　手动导入新材料触发更新**（来源：M01、ADR 0008；Must）
- Given 项目中已有一个已受控的节点范围，When 我手动导入新材料，Then 导入前显示本次将匹配的目标节点范围与预计额度，任务可取消。
- Given 我已导入 2026 Q2 季报且内容指纹未变化，When 我再次手动导入同一文件，Then 不产生新的候选更新，并提示「无实质变化」。
- Given 我查看更新设置，When 页面渲染，Then 只显示手动更新的范围与最近一次导入时间，不出现频率配置与「下次检查时间」。

**US-04　目标时间范围与实际覆盖分开**（来源：G01、D13、OD-01；Must）
- Given 我尚未指定目标时间范围，When 查看项目信息，Then 显示「未指定」，不默认套用近一年或近三年。
- Given 我已设定目标范围但实际材料只覆盖其中一段，When 查看，Then 目标范围与实际材料覆盖分别显示，缺口可见。
- Given 设定的具体起止日期与控件形态尚未确定（OD-01），When 实现该控件，Then 不预设默认区间（本条沿用 OD-01 的 OPEN 状态，不在本文预设区间）。

**US-05　任务进度、用量与故障可见**（来源：N01、N02、D33；Must）
- Given 一个长任务正在运行，When 我查看任务状态，Then 显示阶段进度、已消耗额度（或「未知」，不填零）与已发生的重试次数。
- Given 任务失败或超时，When 我重试同一操作，Then 最多产生一次可见变更，已成功的阶段被复用。
- Given 我已经取消任务但后端结果晚到，When 结果返回，Then 不自动应用到我的图谱。
- Given 首版不设置费用硬上限（D33），When 费用达到某数额，Then 不暂停任务，只如实记录与展示。

### 活动 B　自动重建与公开资料查证

| ID | 我想要…… | 依据 | 优先级 |
| --- | --- | --- | --- |
| US-06 | 提交观点后自动得到候选作者论证链，显示前提、推导与结论，并标出作者表达与 AI 推断，以便我不必先手工搭图 | D48、I02、D07 | Must |
| US-07 | 在本次研究任务内看到各项主张与推导的查证结果（支持／相反／证据不足／暂无法核验）与各自原因，以便我知道哪些有了依据、哪些仍是缺口 | E05、D48、D16 | Must |
| US-08 | 在研究卡上先看一句查证摘要，需要时再点开完整依据、范围与限制，以便我扫一眼就知道是否值得深看 | D54、E05、D43 | Must |
| US-09 | 在图上直接分辨作者表达、AI 推断与我的判断，且不依赖颜色，以便截图或灰度浏览时也不会误读 | G01、D54、ADR 0016 | Must |

**US-06　自动重建候选作者论证链**（来源：D48、I02、D07；Must）
- Given 我提交了观点或一批材料，When 重建完成，Then 画布上从左向右生成候选链：前提 → 推导 → 结论，每张卡带来源入口。
- Given 原文没有写出推导桥梁，When 查看该步推导，Then 明确标注「AI 推断」或「原文未说明」，不被收录行为改写为作者表达。
- Given 同一批材料能整理出多条核心链，When 查看候选，Then 链之间的分歧保留，不强行合并成一条。
- Given 材料稀疏或结论互相不一致，When 重建完成，Then 直接标注稀疏或不一致，不为凑数量补造作者动机。

**US-07　本次任务内的公开资料查证**（来源：E05、D48、D16；Must）
- Given 候选链已生成，When 查证运行，Then 对每个主张与整步推导分别给出：找到支持依据／发现相反依据／证据不足／暂无法核验，并附来源、时间、口径与锚点。
- Given 某项查证失败或只覆盖部分期间，When 查看结果，Then 保留失败或覆盖不足的原因，显示「等待观察」或「口径不可比」等具体状态，不压成通过／不通过。
- Given 我只是打开查证浮窗浏览，When 浏览期间，Then 不触发新的外部查证任务；再次查证需本人主动发起。
- Given 查证使用的目标内容版本后来被我改动，When 查看旧结果，Then 旧结果仍归旧版本并显示版本提示，受影响对象提示重新查证。

**US-08　一句摘要与完整依据分层**（来源：D54、E05、D43；Must）
- Given 研究卡上有一条查证结果，When 我未展开，Then 卡片上显示状态标签与一句摘要，摘要如实说明当前材料或缺口。
- Given 我点击查证区，When 打开详情，Then 显示完整依据、覆盖范围、限制与未解缺口，支持与相反依据可并列。
- Given 摘要的内容来自 AI 候选意见，When 我查看，Then 摘要不写成「本人已确认」的人工评估结论。

**US-09　归属可分辨**（来源：G01、D54、ADR 0016；Must）
- Given 画布上有作者候选、AI 推断与本人内容，When 我查看任意卡片，Then 有统一的文字标签（作者观点／AI 推断／我的判断）区分；灰度查看或截图时也不因缺少底色区分而误读。
- Given 我使用键盘或读屏，When 选中卡片，Then 归属信息可被朗读，不只靠图标与颜色。

### 活动 C　按需核对与收录

| ID | 我想要…… | 依据 | 优先级 |
| --- | --- | --- | --- |
| US-10 | 只核对准备收录的那条链及其前提，其余保留「待核对」，以便我的注意力只花在要用的一 | D15、I04 | Must |
| US-11 | 把还没核对的内容先收录为个人研究草稿并保留「待核对」标记，以便不阻塞后续整理 | D21、I04 | Must |

**US-10　按需核对**（来源：D15、I04；Must）
- Given 完整候选图已展示，When 我只核对准备收录的一条链，Then 该链及其前提标记为已核对，其余内容保持「待核对」不变。
- Given 我完成了某条主张的重建核对，When 查看其个人立场，Then 仍为「待研究」；核对不自动等同于认可（ADR 0004、D15）。
- Given 无法确定某个候选是否与现有对象相同，When 系统发现相似候选，Then 进入待合并列表并给出相似依据，是否合并由我选择。

**US-11　收录为个人研究草稿**（来源：D21、I04；Must）
- Given 有一批候选尚未逐项核对，When 我明确收录，Then 进入个人论证并保留「待核对」标记与原作者版本。
- Given 我收录后再次分析同一批材料，When 分析完成，Then 我编辑过的内容不被覆盖，再次分析可复用已有结果。
- Given 原型当前只支持整条候选链一次性收录（README 已注明），When 我要部分选取，Then 当前需先整体收录再删除不要的节点；此处的「逐项／批量勾选采用」仍待接入（见第 12 节登记）。

**US-36　自动保存与主动记录判断**（来源：D36；Must）
- Given 我正在编辑，When 发生修改，Then 自动保存并写入编辑历史，界面显示保存中／已保存／保存失败的实际状态。
- Given 我想留下一次完整的判断快照，When 点「记录这次判断」，Then 保存当次图谱与内容版本、个人立场、作者对照基线、所用材料与识别文本版本、条件评估及依据。
- Given 我只是在日常编辑或改了条件结论，When 系统检查是否自动生成历史判断，Then 不自动生成。
- Given 保存失败，When 失败发生，Then 保留待同步副本并提示重试，禁止展示为已保存。

**US-37　历史判断回放**（来源：D28、ADR 0009；Must）
- Given 我打开一次已保存的历史判断，When 回放，Then 默认展示该次记录引用的材料、识别文本与评估版本，遵守当次获取时间与版本边界。
- Given 后来新增或修订了材料，When 回看，Then 作为差异另行对照，不倒灌为当时已知。
- Given 我想用今天已知的信息重新审视旧判断，When 主动切换，Then 这是显式操作，新增评估与修订记录，不改写原历史记录。

**US-38　导出两类产物**（来源：S01、D37、OD-18；Must）
- Given 我要迁移完整研究资产，When 导出 JSON，Then 包含节点、边、条件、证据关联、版本与来源清单，不丢失来源 ID、时间与单位。
- Given 我要阅读或继续编辑，When 导出 Markdown 摘要，Then 呈现个人判断、各前提及其立场与理由、条件路径与引用出处，并保留时间与版本；对推导的质疑或不认可按整步单独呈现，采用的 AI 起草理由保留 AI 来源与我的确认或修改记录。
- Given 有些原文无法合法导出，When 导出，Then 提供来源索引与说明，不伪造原文。

**US-39　备份、恢复与删除**（来源：S01、ADR 0015；Must）
- Given 本机运行，When I 备份，Then 提供数据库在线备份快照与完整 JSON 两条本机备份。
- Given 我要删除一个项目，When 执行，Then 需确认，并给出预计清理时间与恢复窗口剩余天数，清除覆盖主库与全部本机备份副本。
- Given 尚未完成一次完整恢复实测（OD-07），When 上线前评估，Then 未实测不得视为可用。

### F7　关键状态机

| 对象 | 状态 | 迁移触发 |
| --- | --- | --- |
| 重建核对状态 | 待核对 → 已核对 | 仅本人核对动作；**不由收录、查证成功、AI 建议触发** |
| 个人立场（主张／整步推导） | 待研究 → 认可／质疑／不认可（四态互相可转） | 仅本人标注；质疑／不认可须附理由（D38） |
| 条件状态 | 未配置 → 可评估 → 满足／未满足／等待观察／未知／不可比 | 计算结果与 AI 建议只形成候选；**满足条件与否由本人确认**（D18） |
| 需复核标记 | 有／无 | 新材料触发「有」；本人完成修订判断或维持原判断后清除；稍后处理保留 |
| 复核结果 | 修订判断／维持原判断／稍后处理 | 仅本人审阅时选择（D23） |
| 候选 | 待审阅／已接受／编辑后接受／已拒绝／稍后／已过期 | 目标版本变化时旧候选过期，需重新检查（I04、M03） |
| 任务 | 排队／运行／部分完成／成功／失败／取消 | 取消停止后续可停步骤；重试复用成功阶段（N01） |

**四组状态互不可推导**：重建核对状态、个人立场、条件状态、复核结果（＋需复核标记）分别记录，互不覆盖（PRD 10）。这是验收时最容易走偏的一条，测试用例须逐组正反验证。

## 09　异常处理清单（与 UI 直接相关的部分）

| 场景 | 期望行为 | 依据 |

| AI 起草理由时材料不足 | 保留缺口，不编造引用 | D39 |
| AI 评估建议与已有人工评估结论冲突 | 展示为独立条目并提示待确认，不覆盖人工结论 | ADR 0005 |
| 重复导入同一材料 | 不产生重复候选，提示无实质变化 | M01 |

| 新的重述版本出现 | 重新提醒并写明差异，旧快照可回看 | E04、M04 |
| 达到建议处理规模 | 提前提示并分批处理，不截断后声称完整 | N01 |
