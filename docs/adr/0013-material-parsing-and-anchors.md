# 材料解析与证据锚点：文本层定位、三级指纹与失效重定位

证据面板的验收标准（E01）要求「点击证据能打开对应页或原文片段」，而 E02 又要求「相同文件以内容指纹去重，转载与近似文本保留来源关系，不能把重复转载计作独立佐证」。这两条决定了解析管线必须同时产出两样东西：稳定的字符级锚点，和能区分「同一份内容」「转载」「近似修订」的指纹。访谈 D34 已确认首版直接支持截图与扫描版 PDF：这类材料识别文字后必须保留原图、页码（适用时）与图像区域定位，识别文本不自动视为已核对原文。用户随后澄清希望使用多模态模型，首版据此采用多模态模型识别图像文字；具体模型、供应商与解析产物结构仍待样本验证（OD-24）。此处 OCR 是任务名称，不表示已经选定独立的传统 OCR 引擎。文本型 PDF 走 `pdfjs-dist` 6.3.289 的文本层提取，在 Node worker 线程中读取每个文本项的字符串与变换矩阵，重建归一化页面文本并保存「页面字符偏移 ↔ 原始坐标」的映射，锚点记为 `{kind:'pdf', page, char_start, char_end, bbox, prefix, suffix, table_ref?}`。表格不做通用结构识别：pdf.js 不产出表格语义，P0 只做「页码 + 表格序号 + 行列头匹配」的候选定位，由用户在核对页确认行列头后把结果记为 `table_ref`，未能确认的标为待核对而不是猜测取值（E03、PRD 第 07 节的 P0/P1 分层）。网页锚点记为 `{kind:'web', canonical_url, text_fragment, prefix, suffix, dom_path}`，其中 `text_fragment` 采用 W3C Text Fragments 语法（Chrome/Edge 80+/83+、Firefox 131+、Safari 16.1+ 均已支持），`dom_path` 作为文本片段失效时的二级定位，另外在授权允许时保存本地快照（S01）。精确材料指纹采用原始文件或实际获取内容字节的 SHA-256，记为 `content_fingerprint`；来源版本仅在同项目、同来源身份内去重。规范化文本指纹与 SimHash（`similarity_sketch`）用于提示可能的转载或近似修订，不作为精确材料身份，也不自动合并不同来源；转载关系须有出处依据，无法确定时保留待核对候选。不同出处或项目的相同字节仍分别保存来源身份、权利与获取时间，可复用底层文件但须保留项目访问边界。段落级 `block_fingerprint` 支撑同一来源版本内的段落去重与锚点重定位。转载在佐证计数时按 canonical 内容归一，只显示「转载自某出处」，不计为独立佐证。锚点失效时不做静默替换：先用原文片段加前后缀在窗口内做模糊重定位，成功则把状态改为 `relocated` 并更新偏移，失败则改为 `broken`、保留快照与旧定位并告警，无快照时显示不可复核而不捏造原文（E01 异常）。若仅取得全文转写而不保存原图与区域映射，引用将无法精确回查；因此不论采用本机 OCR 还是外部识别服务，都须生成可回到原图的定位，并保留原文件去重。相较引入 Python 的 PDF 工具链（表格与版面解析更强），代价是第二套运行时与跨进程任务编排，而 P0 只验证少量字段、表格结构识别属于 P1。财务白名单字段清单首版不锁定，待首个案例材料到位后按真实论证涉及的指标反推（本人裁定），因此解析器不针对任何具体字段名硬编码，只保证抽出的每个值都带齐十项必备属性（主体、指标、原始值、期间、币种、单位、合并范围、累计或单季、披露版本、来源锚点），并一律遵守「未知不填零」与「不可比即中止跨期计算」两条规则。截图与扫描版 PDF OCR 已纳入 P0（D34），复杂版式与通用表格结构识别仍为 P1；识别失败或部分成功须显示实际覆盖与缺口，保留原图及成功识别的内容，允许补交文本，不得伪装为已完整读取。影响是：解析器输出归一化文本、文本定位与适用的原图区域映射，不输出论证或条件判断；解析失败必须落到 `source_versions.parse_status` 并给出受限访问、损坏文件、OCR 失败、无法读清的图像或未知编码的具体原因，不得仅因材料是扫描件便判不支持。

## 实现约束

- 归一化规则必须版本化（`normalizer_version`），规则变更不得回溯改写既有指纹。
- 当前单机实现按 ADR 0018 将原文件字节存 SQLite BLOB，来源版本引用文件身份；正文与定位产物分别保存。替代原先 `source_versions.storage_path` 的具体存储方式，删除时仍一并清理（S01）。
- 只处理用户提供的文本、文本型 PDF、截图、扫描版 PDF 与明确有访问权的链接，不绕过登录或付费限制（AGENTS.md、D34）。
- 识别文本与原图分别保存，引用保留页码（适用时）和图像区域；记录实际成功识别与失败的页或区域，无法读清的内容标明缺口。OCR 完成不自动完成重建核对，也不自动改变个人立场或人工条件结论。
- 按 D35 提供应用内原图对照与转写校正入口；保留模型初始转写、人工校正版本及修改者、时间、修改前后内容。转写校正不改变原图或来源获取时间，不归为作者原文修订；既有证据和历史判断仍能引用旧识别产物版本。
- 保存校正后仅重新分析受影响内容，生成候选或影响建议供本人审阅；任务与缓存须区分识别产物版本，不用旧转写的分析结果响应新校正版本。
- 多模态识别按原图或扫描页建立转写结果，并与后续主张提取、摘要和 AI 推断分别记录。模型给出的坐标须与原图及其缩放、裁剪关系核验；仅在转写文本中找到引用不等于已核验原图内容，未验证定位不得标为有效锚点。
- 技术核查依据：[Gemini 图像理解文档](https://ai.google.dev/gemini-api/docs/image-understanding)说明图像输入与边界框输出；[Claude Vision 文档](https://platform.claude.com/docs/en/build-with-claude/vision)说明坐标和定位为近似结果。这些是接口能力与限制依据，不证明某供应商符合 D30，也不构成本项目样本识别质量的实测结果。
- OCR 如需外部服务，沿用 D30 的任务级发送范围与供应商条款要求；费用沿用 D33，仅记录实际用量与费用，不设费用硬上限。
- 导入任务按文件独立记录成功、失败与跳过原因，支持部分继续，不需整批重来（I01）。
- 抽取结果不得因白名单未定而放宽校验：字段缺失标为缺失，口径不一致标为不可比，两者都不进入计算。


## 2026-10-08 实现边界

文本层、HTML 路径、SHA-256、原文件 BLOB、逐页原图渲染、模型转写接口、人工校正与受影响任务已有代码和隔离测试。SimHash、段落指纹、失效锚点候选重定位、`table_ref` 人工确认仍未实现；本 ADR 的方向不是完成声明。真实多模态模型及财报样本尚未通过验收，详见后端实施进度与 ADR 0018。
