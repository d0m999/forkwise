# 图标统一采用 Lucide，视觉不依赖 emoji 与渐变

PRD 第 04 节要求「状态不能只靠颜色区分」，而论证图谱里有归属（作者论证、AI 推断、个人论证）、个人立场（待研究、认可、质疑、不认可）、重建核对状态、条件状态、候选状态、证据关系等多组语义，若用 emoji 表达，一则不同平台的字形与配色不可控，二则无法随设计令牌改变颜色与描边，三则读屏软件会读出难以理解的字符名。决定全项目统一采用 Lucide 图标库（`lucide-react` 1.49.0，MIT 许可，24×24 网格、2px 描边、按图标 tree-shaking、颜色默认继承 `currentColor`），禁止使用 emoji 作为功能图标，禁止混用第二套图标库。相较 Tabler Icons 与 Phosphor（图标总数更多、风格更丰富），Lucide 的取舍是造型更克制、复杂语义（如「合并范围」「重述」）可能需要组合表达，换来的是与 React 19 的官方适配、稳定的命名规范与最小的包体增量；相较 Heroicons（与 Tailwind 同源），Lucide 的覆盖面对本项目的财务与状态类图标更完整。视觉层面同时锁定：不采用紫到粉的渐变作为主视觉，不在组件里硬编码颜色值，全部颜色、圆角、间距与字阶来自 CSS 变量形式的设计令牌，图标颜色一律继承文本颜色。影响是：图标语义需要一份「语义到图标名」的映射表并随领域模型维护，新增语义先查映射表再找图标，不允许临时替换；所有图标必须带无障碍标签或在容器上提供可读文本，不允许只有图标没有文字的状态表达。

## 尺寸规范

| 尺寸 | 像素 | 用途 |
| --- | --- | --- |
| 16 | 16×16 | 节点卡内的状态徽章、表格行内标记、密集列表 |
| 20 | 20×20 | 面板内表单控件、按钮内图标、侧栏菜单项 |
| 24 | 24×24 | 主工具栏、空状态插画、对话框标题旁图标 |

同一视图内同一语义的图标尺寸必须一致；不得通过缩放非标尺寸（如 18、22）来凑布局，需要中间尺寸时从三档中选择最接近的一档并用间距调整。

## 实现约束

- 图标颜色继承 `currentColor`，只在语义色令牌下改变文本颜色，不对图标单独设色。
- 状态表达必须「图标 + 文字标签」成对出现，颜色只作为辅助（PRD 第 04 节）。
- 禁止紫到粉渐变；禁止在组件中写十六进制颜色常量；令牌定义在唯一的样式入口文件中。
- 不引入组件库，Tabs / Dialog / DropdownMenu / Tooltip / Popover 等交互原语如需外部实现须另立 ADR 并锁定版本；自研原语必须满足焦点可见与键盘可达。
