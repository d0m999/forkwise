# 条件状态由人工确认，AI 评估意见独立保留

首版需要 AI 提供条件是否满足的评估意见，同时由研究者负责确认结果。决定将有理由、引用与缺失信息的 AI 评估建议和人工评估结论分开记录，条件状态以研究者确认的结果为准，未经确认的新建议不能替换已有人工结论。相较原 PRD 允许白名单规则自动确定条件状态的方案，此选择保留明确的人工审阅步骤，以支持材料不完整或含定性判断的研究场景。

D114（2026-10-08）进一步确认条件作为独立规则对象，保存判定要求、适用主体、期间与口径，可被多项陈述或推导引用，独立编辑并保留规则历史。相较把相同条件分别嵌入各项内容，此方案增加独立对象与引用，但让规则有明确身份，能够复用和追溯。定性与结构化规则均可承载，不以示例指标确定首版白名单。

条件规则负责说明“怎样判断”，陈述、推导及个人立场保持各自责任。规则对象独立不等于自动确认评估，也不要求独立画布卡片。共享修改范围、引用规则版本的具体方式及字段继续设计。

D115（2026-10-08）确认每次条件评估具有独立身份，绑定所用条件规则版本、材料版本、评估时点、评估者与结果，业务期间及依据另行保留。相较把结果仅作为条件内部属性，此方案增加可独立引用的评估记录，使历史判断能够精确回到某一次评估；新评估不覆盖旧记录的结果与依据。规则计算、AI 意见与人工确认继续分别记录，不以最新计算替换本人确认或个人立场。

D116（2026-10-08）确认：已支持确定性计算的结构化条件修改阈值保存后，本地必需输入齐全且可比时，自动生成新计算记录，绑定修改后的规则与实际使用的材料版本。相较要求本人另行点击重算，此方案减少重复操作，并使新规则及时得到计算反馈；新结果仍待本人确认，旧评估与人工确认历史保留。仅使用已有本地资料，不获取新数据或调用模型；缺失、不可比或不支持时不虚构结果、不默认判为未满足。

D117（2026-10-08）确认 D116 场景中规则保存与计算分别处理：保存成功后，计算失败不撤回阈值修改，明确显示已保存与计算失败，并允许单独重试计算。相较要求两者一起成功，此方案保留已完成的规则编辑；代价是界面与业务流程需要分别呈现保存状态和计算状态。计算失败不等于条件未满足，旧评估继续明确绑定旧规则，不能冒充新规则结果。保存本身失败仍不得显示成功；D92 的关联图谱写入事务约束保持。

条件评估还包括无法表达成公式的定性判断。确定性工具与 Agent 的执行分工、Agent 触发策略、同步或异步执行、候选材料的选取、其他重评估时机、当前结果选取、记录更正与幂等、具体存储方式继续设计；本决定不确定整链批量操作的整体成败边界。本轮仅维护文档，未修改正式实现。
