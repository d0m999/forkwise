# 业务批次的持久化操作历史

2026-10-09，依据 D118 auto-select 授权实施 D136，并由 D137 补齐首次研究分组。

当前对象历史适合审计与固定版本回看，不能单独表达一次删除的连带变化、布局或一个完整拖动。采用独立的每项目操作栈，保存最近 40 步及游标，与业务变更、布局和幂等回执在同一 SQLite 事务内写入。条目只引用已有不可变对象版本；呈现变化保存操作前后布局内容，不记录视口、选择、返回位置和未提交表单。

撤销是一项新写入，不覆盖旧审计行。恢复此前的内容版本身份和领域数据，同时递增写入版本、项目修订及操作历史版本；如此既能重新匹配原证据/评估上下文，又能拒绝基于旧写入版本的并发保存。普通业务写入、HTTP、MCP 和前端共用同一服务约束。历史旅行要求本人会话，因为恢复立场、人工确认或参与状态同样是在改变个人研究判断。

已导入来源、来源版本和文件资产不参与研究编辑撤销。撤销只改变它们与研究对象的使用关系。任务执行记录及不可变审计保留；恢复旧内容不会主动调用模型或重算。新发起的首次研究在请求时建立一个步骤，各阶段只追加新候选对象到同一步；期间本人编辑仍独立。独立评估与其他研究任务保持按批次记录，升级前的旧任务不推测合并。

完整工作区和增量同步附带下一步动作名称、操作历史版本。旅行请求必须同时匹配项目修订、布局版本和历史版本；错序或缺少相关历史时整批拒绝，不静默拼接。未知结果复用原幂等键。连续原生绘图状态只在明确完成动作时提交内容，视口和草稿可独立持久化，撤销恢复内容时保留当前导航及输入。

项目 JSON 的可选 `actionHistory` 保留栈与游标；旧存档缺省为空。导入检查版本引用、当前状态一致性及顺序回放的图谱约束。历史中的布局图片也须按来源权利过滤；SQLite 指纹 v3 纳入操作栈；v4 再纳入研究分组和任务归属表，旧指纹版本不改变计算范围。项目最终清除同步清理这些表。

代价是历史布局前后快照会增加图片和绘图的存储量，当前 40 步上限不等于大材料容量验收；后续需测量并考虑快照/文件去重。旧原型栈转换和真实大存档验收保持未完成。已有业务、HTTP、MCP、磁盘重启、故障回滚和浏览器证据分别记录在后端实现进度中。


D137 的工作流分组独立于有限操作栈持久保存。撤销同时使分组停止、取消活跃子任务并使运行令牌失效，提交成功后才向运行实例发出中断；事务回滚时不提前中断外部调用。重做只恢复已经完成的结果，分组仍禁止继续执行，任务重试不能重新打开它。停止标记不会随 40 步淘汰或重做分支截断丢失。

分组只允许追加此前不存在的候选对象，不允许合并已有内容或布局变化，避免穿越期间发生的本人编辑。异步追加会推进操作历史版本并清除重做分支；原步骤退出窗口后不再插入替代步骤。JSON 分别保存分组归属、停止标记与可选操作栈，恢复前校验父子任务、归属唯一性、执行状态与栈游标；单纯任务执行状态不能推导图谱结果是否仍被保留。


D138 补充原生完成动作的无变化判定：完整状态相同且没有待完成内容变化时不派发空状态事件，覆盖初始化后的空闲计时器。若连续事件已经更新本地状态，但仍有待提交的真实内容变化，最终动作仍派发以形成历史步骤。不能只按最近一次状态相同就丢掉真实完成动作，也不能把空闲计时器本身当成用户编辑。
