# 部署只做本机运行，备份只做本机副本与导出 JSON

访谈 D29 已确认首版采用本机 Web（应用在本机运行，材料与图谱在本机保存），本人又裁定访问范围**仅本机、不做远程、不做多端同步、也不为远程预留结构**。S01 要求项目、来源、图谱与批注默认仅本人可见，且正式保留期与备份清除机制需在上线前确定并测试。据此决定：后端只绑定回环地址，本机单人免应用账号登录，保留 D31 的本地会话访问校验；不提供远程访问、分享、多端同步或远端应用服务配置；数据库是本机单个 SQLite 文件，原文与快照存于本机项目数据目录；出网范围限于本人发起任务所需、有权访问的材料链接读取或手动刷新（D14、M01），以及按 D30／ADR 0014 限定的模型调用；不自动监控来源，也不自动外传行为或无关项目数据。备份只做本机方案两条：一是数据库在线备份命令生成的一致性快照文件，二是按领域模型第 12 节键清单导出的完整 JSON（含节点、边、条件、证据关联、版本与来源清单）；两者都落在本机备份目录，不做云端、不做外部存储、不做自动异地复制。恢复窗口默认值定为 **30 天**，可在设置中调整——这是可调默认值而非服务承诺，是否调整由本人按需决定。上线前必须实测一次完整恢复：从备份副本恢复到隔离目录，逐项核对节点、边、条件、证据关联、版本与来源清单是否齐全且与导出 JSON 一致；**未实测不得视为可用**。删除仍须提供确认步骤与预计清理时间，并覆盖备份副本而不只是主库（S01）。相较部署到自托管或云端（可获得远程访问与多设备同步），该方案被明确排除：本人裁定不做远程，因此不预留远程账户、远程鉴权或远程传输加密结构，日后若要远程须重新立项并另立 ADR，而不是在本方案上开一个开关。相较在本机之外再挂一份外部备份（可抗整机丢失），代价是要把私有语料送出本机并引入第二个信任边界，与「默认私有」的姿态冲突；本机方案的真实风险是整机丢失，只能由本人自行把备份文件与导出 JSON 复制到自己掌控的介质，产品侧不代劳也不承诺。相较完全不做备份，代价是硬盘故障即丢失多年研究资产，这对一个以长期积累的推理与判断演变属于用户为价值主张的产品不可接受。影响是：安装、升级、备份与恢复都必须是单机可完成的操作并在界面上给出明确入口；日志记录在本机且不得写入完整敏感原文（S02）；`retention_days` 以 30 为默认值落进设置项，清除任务必须能证明备份副本中已不含该数据。

## 首版访问方式（访谈 D31）

用户在 Q31 中选择本机单人直接打开使用，不另设应用账号或密码。服务保留回环监听与本地会话访问校验，原文件、索引与导出下载同样受保护；外部模型凭据独立于应用登录处理。

## 实现约束

- 只允许回环绑定，保留 D31 的本地会话访问校验；不提供远端应用服务地址、远程应用账户凭据或同步开关。ADR 0014 所需的外部模型端点与凭据独立管理。
- 备份产物与导出文件同样受授权范围限制：无法合法导出的原文只导出来源索引与说明（S01）。
- 恢复流程必须在设置页可见可操作：选择备份副本 → 恢复到隔离目录 → 逐项校验 → 确认后再覆盖当前数据；任一步失败都要保留现场并给出原因。
- 删除流程必须给出确认、预计清理时间与恢复窗口剩余天数；超过窗口即不可恢复，界面须在删除前明说。
- `retention_days` 默认 30 天，改值不需要改代码；清除任务必须覆盖主库与全部本机备份副本。
