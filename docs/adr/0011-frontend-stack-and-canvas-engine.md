# 前端采用 Vite + React 单页应用，画布引擎选用 React Flow

本 ADR 记录生产应用的既有 React Flow 选型。D51 两库完整编辑器试验属于历史临时原型，D52 移除 tldraw，D53 当前试验为完整 Excalidraw 与研究操作融合在同一画布，原研究画布仅作直接打开 HTML 的兼容回退；tldraw 仅作设计参考。本次没有决定采用 Excalidraw 生产，也未将原型安装版本写入下方生产锁定表。

部署形态已由访谈 D29 确认为本机 Web——应用在本机运行，材料与图谱在本机保存，后续按需再考虑 Swift 外壳——因此前端是一个跑在本机浏览器里、访问本机服务的单页应用，无需实现离线同步与多端状态合并；外部材料读取和模型任务的断网、限流、有限重试仍按 N01 处理。此前的 Excalidraw MCP 实验流程与手写 SVG 演示提供了探索经验；核心研究交互仍须按 D41–D53 验证，旧演示原型已因与当前需求冲突而删除（OD-22）。本 ADR 形成时，首版画布优先解决结构化研究编辑：节点与边由数据驱动、连接时阻止成环并给出解释（G03）、折叠后代而不删除数据、把同一推导步的多条边作为一组高亮（D27）、按建议的 100 节点规模验证搜索定位与局部展开。决定前端采用 Vite 8.3.1 + React 19.3.0 的单页应用，画布引擎选用 `@xyflow/react` 12.12.0，自动布局用 `@dagrejs/dagre` 3.1.1，Excalidraw 不作为生产编辑器；本人直接在自由画布梳理和编辑结构化论证，聚焦、检查提示与按需 AI 提问嵌入同一画布（D47）。相较沿用 Excalidraw（自由绘制与手写批注体验好，也已有实验积累），它的场景元素不是论证对象，节点与边没有语义身份，防环、局部版本作用域、推导步分组都要在两套数据模型之间做同步，且包体与画布交互模型都围绕「画」而不是「编辑结构化图」设计；相较继续手写 SVG 画布（对视觉细节有完全控制，曾有界面演示，核心交互尚未完成验证），需要自行补齐平移缩放、命中测试、键盘操作与无障碍支持，这些工作量换不来任何产品差异。这一选择的代价是：在当时的首版范围内未纳入自由绘制与随手批注，画布视觉受节点卡模型的约束，遇到特殊排版需求要写自定义节点组件而非直接摆放。影响是：节点与边必须由 `edges` 与 `joint_inferences` 派生渲染（见领域模型 2.7），自定义节点组件只允许读取 props 不允许持有图谱状态，所有写图操作走唯一的 `GraphWriteService` 以便防环校验只有一处实现；本机运行意味着前端只能通过回环地址访问后端，不得引入任何形式的远端 API 配置。

## 画布实现约束

- 研究对象的视觉呈现以后续确认的 D54 与 PRD 第 04 节为准：完整主张、高度自适应、中性底色与归属标签、独立个人立场、查证状态加一句摘要及常驻来源入口；推导关系使用连线窄条，保留领域对象及整步立场。详细解释、完整查证依据、核对过程、版本与编辑表单进入画布内按需浮窗，不设置常驻的材料栏与对象详情栏（D49）；左侧项目导航按 D55 可折叠，进入研究后默认收起，可固定展开。D54 视觉已应用到融合原型，仍待本人评审；D55–D59 导航、顶部入口、中央输入与原版对照浮窗已应用到原型，具体实现与限制见 `prototype/README.md`，不改变本 ADR 的生产引擎决定。
- 状态不能只靠颜色区分，必须同时有文字标签与图标（PRD 第 04 节）；图标一律来自 ADR 0016 锁定的图标库。
- 选中一条边时，按 `joint_inference_id` 高亮同组全部边，并在按需打开的对象详情浮窗显示该推导步的个人立场与前提列表；已打开的浮窗与当前对象联动（D43、D49）。
- 折叠只影响渲染，不写 `edges`；展开后保留原有选择与定位（G03）。
- 拖拽之外必须保留键盘与列表式编辑入口（PRD 第 04 节）。
- D50 明确拖 A 卡片到 B 卡片表示 B → A，且同一主张可有多个后续主张。生产连接仍通过领域推导对象与唯一写入入口记录，不改为每张卡仅存一个父节点的树模型；联合推导与整步立场继续按 D27 保留。

## 开放卡片入口的首个适配切片（Issue #2，2026-10-13）

沿用 React Flow 生产选型，在 `frontend/` 安装 `@xyflow/react` 12.12.0、React 19.3.0 与 Vite 8.3.1。普通卡片的领域身份、标题和正文由 Mapping 持久层提供，自定义节点只接收投影和编辑回调；不把旧主张或推导语义套到新卡。该切片验证创建、独立标题/简单正文、项目切换和重启恢复；其他对象、复杂交互及规模仍须逐票验证。

`backend` 的原 `build:canvas` 继续用于 Excalidraw 原型，不能据其命名推定生产引擎已切换。新增 `build:workspace` 和 `start:workspace` 为正式开放卡片入口，要求显式独立数据目录，不调用旧库迁移、恢复或清理。原入口与资源保留，具体操作见 [开放工作台说明](../open-workspace.md)。实现证据由本机 Issue #2 记录固定；此段不宣称已通过独立审查或整套产品验收。
