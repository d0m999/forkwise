# 开放工作台：本机第一张卡

本入口使用 ADR0011 已选择的 React Flow。现阶段支持项目创建、重命名、切换，以及普通卡片独立标题、简单正文和位置的 SQLite 自动保存。正文与位置可同时保存，互不覆盖。旧研究入口、原型及其数据库保持原样；不自动导入旧项目。本阶段提供最小拖动持久化，以及具明确项目编辑委托的调用者共用的 Mapping 写入口。完整摆放、吸附与多选（#8）、完整恢复（#5）和完整 Agent 产品交互（#38）仍待后续实施；不提供富文本或资料迁移。

## 安装与启动

需要 Node.js >=22.22.2。在仓库根目录安装锁定依赖：

```sh
npm --prefix frontend ci
npm --prefix backend ci
npm --prefix backend run build:workspace
```

选择一个新的绝对路径作为数据目录，再启动：

```sh
FORKWISE_DATA_DIR="$HOME/Library/Application Support/Forkwise/Open Workspace" npm --prefix backend run start:workspace
```

启动后，使用当前本机账户读取该目录的 `local-access.json`，在本机浏览器打开其中的 `url`。该文件仅本人可读（0600），数据目录仅本人可访问（0700）；启动不会自动放宽或更改已有权限。URL 中的临时凭证通过片段传给页面，换取 HttpOnly 会话后立即从地址栏清除；启动日志不打印凭证。直接访问裸地址不会获得项目访问权。关闭进程后，以**相同目录**启动即可重开。端口占用时显式设置 `FORKWISE_PORT`。本入口要求独立目录，拒绝旧资料目录、未知格式、符号链接、多硬链接文件及缺失主库的残留 WAL/SHM；没有自动搬运、覆盖或修复原件操作。

旧 `npm --prefix backend start` / 8787 入口没有改变。不要用旧启动命令验证新卡片，也不要把用户旧 `.data` 指定为本入口目录。新入口的构建或启动失败不会替换旧入口。

## 使用

- 「新建研究」直接打开空画布，顶部项目标签切换项目，「重命名」单独改项目名称。
- 「见岔」展开紧凑项目导航，可固定。项目编号用于区分同名项目。
- 点击底部「卡片」，再点击画布放置；键盘聚焦「卡片」后按 Enter 在可见画布中央创建。
- 卡片标题可独立编辑，Enter 完成、Shift+Enter 换行、Esc 保留。中文组合输入结束前不触发完成。
- 拖动卡片的非编辑区域可保存位置；键盘聚焦卡片的移动按钮后，用方向键调整位置。写正文时可以移动卡片，两类保存独立校验版本。
- 「编辑正文」打开右侧简单正文输入。编辑自动保存；只有 SQLite 写入及回读成功才显示「已保存到本机」。未保存时离开页面有浏览器提示；保存失败保留当前输入。标题和正文分别保留待确认输入；旧保存回执不会清掉较新的输入。切项目须等待最新输入确认，目标项目加载期间的新输入也先保存到原项目。
- 同一标题、正文或位置被另一调用者更新时，保留本地输入并显示已保存内容或位置；明确确认后才重试保存。确认前对方再次更新时，会再次提示冲突，不直接覆盖尚未确认的新版本。

当前研究数据只写入专用目录的 `workspace.sqlite` 及其 WAL/SHM；本机启动凭证独立写入同目录的 `local-access.json`。卡片、正文、文本块和画布项有独立稳定身份；标题、正文与位置分别版本化，正文和位置保留独立不可变版本。`Mapping.read/execute/observe` 是本阶段唯一业务读写入口，UI 与可信调用者共用 `execute`：先验证会话身份、项目权限和编辑委托，不能通过请求内容自报 human 获取权限。具明确项目编辑委托的 Agent 可调用该写入口；这不包含完整 Agent 授权管理或交互界面。版本、历史、成功回执和变更同事务保存，跨重启原命令重试不会重复写入。没有使用 localStorage 保存卡片，没有遥测或模型调用。不可变版本与最近40步可撤销动作分别保留；旧版本记录不等于永久可撤销。

## 验证

```sh
npm --prefix backend run check
npm --prefix backend test
npm --prefix backend run build
npm --prefix frontend exec -- playwright test
```

浏览器测试请从 `frontend` 执行 `npx playwright test`，先构建。它自动分配回环端口、新建临时目录、重启正式构建后的服务，并创建全新浏览器上下文；不操作用户浏览器配置或旧存档。可设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 使用已安装 Chromium，测试不修改浏览器二进制权限。否则按 Playwright 的标准方式安装测试 Chromium。

浏览器自动输入中文文字不等于真实系统输入法验收；此项应单独记录。完整开放画布能力按后续工单推进，不能从第一张卡的保存成功推定整个引擎适配完成。

## 项目时间线撤销（Issue #4）

顶部「撤销」「重做」及 ⌘Z / ⌘⇧Z（其他平台 Ctrl+Z / Ctrl+Shift+Z，亦支持 Ctrl+Y）操作当前项目最近40步研究动作，包含本人和具编辑委托的 Agent 修改。当前支持创建普通卡片、标题、简单正文、位置、正文与位置原子编辑及项目改名；项目创建不进入其自身研究历史。无变化保存不占步骤，新研究编辑清 redo。跨卡操作提示实际目标标题，保留已打开的正文面板；不会自动切到被撤销的卡片。

标题编辑中快捷键由文本输入处理；Enter、Esc 或离开标题后按整轮撤销。连续创建与首次标题一步撤销，重做恢复原卡片、Body、Block、Item身份。正文按1秒连续输入间隔、选区/输入类型变化、粘贴、离焦/切卡分组；400ms停止输入保存和2秒最长保存批次不决定撤销粒度。IME组合期间不触发项目快捷键，完成后保存。实际系统输入法需要另行人工验收，合成composition事件不能代替。

撤销先确认本页面待保存正文和布局，再读取最新项目修订；竞争写入造成修订不符时拒绝并提示，不越过新动作。历史操作结果未确认时暂停新输入、项目切换及普通撤销／重做按钮和快捷键；丢 ACK 保持原 commandId，通过「重试撤销」或「重试重做」恢复原动作。确认后才可发起下一次普通历史操作，不用相反方向标签重试旧动作，也不重复撤销下一步。完整跨刷新草稿恢复和冲突副本仍由 #5 及对应对象票完善。

历史查询 `Mapping.read({type:'history', projectId}, principal)` 与 `GET /api/mapping/projects/:id/history` 返回同项目修订下的有序undo/redo动作摘要，末项为下一动作。Agent可读，`history.undo` / `history.redo` 仅本人会话可执行；请求含 `expected: project.revision` 与空payload，身份只取可信会话。成功回执含 `historyTarget`，删除变化含 `deletedIds` 与 `after:null`。撤销只恢复动作实际修改域，并生成新版本，不回用旧版本ID。

`editGroup` 只接受在正文、标题、创建命令上。前端每轮生成新ID；服务端仅合并同会话、同actor、同卡片、同域的相邻写入，连续创建→首次标题是明确例外。其它命令、撤销/重做会截断合并；每次保存仍保留独立版本和delta。栈、回执、身份保留及领域版本同一SQLite事务提交，服务重启后可继续撤销。升级前专用工作台库增加新表，从空可撤销栈开始；已有卡片、版本、回执与旧changefeed保留，不猜测旧编辑组。本票兼容性只使用隔离合成前版库副本验证。

资料与资源目前仍通过旧研究入口的 `source.create/source.import`、真实文件上传/解析入口保存。它们不占该入口研究历史、不清redo、撤销不删原文件；开放工作台暂无资料/资源命令或材料UI。两种入口保留独立数据和历史，未把旧材料静默接入普通卡片。后续材料票须在真实接入时扩展合同与纵向测试。

后续每类对象操作必须在其对应票为明确写域增加同事务历史、版本、delta、身份/删除闭包，并经read/execute/observe、重启和真实UI验证完整undo/redo；不能直接把整对象旧快照覆盖所有域，也不能因为通用历史表存在就宣称新对象已支持。当前无长期历史保留或资源GC承诺。

用户主动清理了旧原型目录时，工作区可执行 `build:workspace`；完整 `build` 的 `build:canvas` 和部分原型迁移测试仍要求原目录。完整提交验证应在该提交的独立归档副本运行，不能以跳过脚本或恢复用户已清理目录掩盖工作区限制。

### 已确认输入、布局顺序与删除态

无变化保存确认只确认该命令原有的 `expected`；后续草稿可以沿该次写入回执的新版本继续保存，但不会借后续回读中另一调用者的版本自动重基。标题与正文的真实并发修改仍提示冲突，并保留本地最新输入。

同页面开始移动时，保留并按顺序提交移动前已经完整结束的正文输入组；几何预览立即响应。未结束的 IME 组合不拆分提交，也不阻塞独立 Pose 保存；组合之前已有的完整输入仍须按原顺序确认。正文已明确冲突时保留双方并允许 Pose 按自身版本保存，之后的明确正文选择作为后续动作。前序命令结果未知时保留位置和原命令，重试确认后再提交布局，不把未知结果当成冲突跳过。移动边界之后的输入在布局请求结束后继续保存；布局请求失败也不阻塞后续正文保存，原布局命令保留供重试。正文与 Pose 分别校验版本，正文 ACK 不拥有布局草稿，拖动中的回读不改变当前手势位置。这一协调限定在当前页面，不预先占用其他调用者的项目时间线。

正文前序命令从未知结果转为明确冲突后，待保存布局仍可通过「重试保存」独立恢复；不需要先采用本地正文。布局自身有版本冲突时仍须明确确认其位置。布局确认不清除正文冲突，也不会把未处理正文显示为全部已保存。

撤销创建成功并移除当前写字板卡片时，保留原卡身份和标题的面板，退出编辑，显示“这张卡片已删除”和“撤销删除”。删除失败或结果尚未确认时不展示成功删除态；晚到保存确认不能把删除对象重新写回。恢复入口先核对对应这次移除的历史动作ID，并使用同次历史查询的revision提交；后续研究编辑清空redo、下一redo属于别的动作或竞争改变修订时，不恢复无关动作，入口停用并说明“这次删除的恢复已不可用”。未知恢复结果保留原命令键供重试。当前面板不暗切别卡，用户仍可主动关闭或打开另一张卡片。
