# 投资推理图谱设计访谈记录

本记录保存对初稿的逐项评审结论与后续产品决定，需求已统一至[当前 PRD v0.2](../prd/投资推理图谱_PRD_v0.2.md)，原 v0.1 独立文件已移除。术语定义另记于 `CONTEXT.md`；满足重要取舍条件的决策另记为 ADR。

## 已确认决策

### D01 首版先服务本人研究流程

用户在 Q1 中选择 A：先给自己用，跑通本人的真实研究流程，再考虑外部用户。

因此，首版优先依据本人使用中的实际问题确定范围与验收标准。PRD 第 13 节面向外部试点用户的完成率与持续回看指标，需要在后续产品化阶段重新评审；本人首个研究任务见 D08 至 D11，其完成标准见 D12，首版完整验收范围尚待明确。

此选择确定使用与验证顺序；部署形态与首版访问方式现已分别在 D29、D31 确定，后续商业模式仍待明确。

### D02 首版同时优先支持理解作者与整理本人推理

用户在 Q2 中选择 A+B：重建 KOL 多年的核心观点、论证与变化，同时把本人的判断拆成前提、条件分支和结果。

这两项均为首版优先任务，不能只以作者摘要代替个人推理。两项任务的衔接方式见 D03，首个案例的完成标准见 D12，新材料的更新范围见 D16。

### D03 从作者论证出发形成个人论证

本节保留当时决定与证据；D66 已调整当前直接研究流程及参与状态，强制先收录或切换候选／个人模式的部分不再作为现行操作前提。

用户在 Q3 中选择 A：先重建 KOL 的论证图，再选取其中的链条形成个人版本，修改前提、增加分支或提出不同结论。

这确定了首版的主工作流：理解作者论证，再形成与修订个人论证。两者的术语定义已记入根目录 `CONTEXT.md`；形成个人版本的认同语义见 D04，原论证与个人版本之间的溯源关系见 D06，作者后续版本的默认对照与合入规则见 D22。

### D04 收录论证不自动表示认同

用户在 Q4 中选择 A：将作者论证复制进个人图谱后默认待研究，认同程度由本人另行标注。

收录与认同是不同的行为，不能以复制操作自动赋予认可状态。术语定义已记入 `CONTEXT.md`；判断标注的粒度见 D05，首版个人立场的完整状态列表见 D24。

### D05 主张与推导关系分别标注研究者立场

用户在 Q5 中选择 A：主张和推导关系都能单独标注。研究者可以认可一个主张，同时质疑从该主张导向另一结论的推导关系。

此选择要求保留两类对象各自的个人立场，不能只为整条链赋状态，也不能仅靠节点备注表达推导异议。下一版 PRD 需补齐推导关系的立场与修订语义；对应决策见 [ADR 0001](adr/0001-separate-claim-and-inference-stance.md)，多前提共同依赖时的标注单位见 D27。

### D06 个人版本与作者原论证逐项对照

对照应覆盖主张与推导关系，而不只是节点文字；被复用或改写的内容保留其所依据的作者版本。对应术语“论证溯源”已记入 `CONTEXT.md`，决策见 [ADR 0002](adr/0002-preserve-argument-lineage.md)；作者后续版本的默认对照与合入规则见 D22。

### D07 允许明确归属的 AI 候选推导

此选择允许论证重建显露并补充隐含前提，同时保留作者表达与 AI 补充的边界；接受候选不能将其归属改为作者原意。对应术语已记入 `CONTEXT.md`，决策见 [ADR 0003](adr/0003-keep-ai-inferences-distinct.md)。

### D17 新材料触发复核提醒而不自动改变个人立场

用户在 Q17 中选择 A：新材料可能反驳已认可的前提时，保留本人原立场，另标“需复核”，由本人审阅后决定是否修订。

原立场及其时间记录保留，复核提醒与个人立场分别表达。术语“需复核”已记入 `CONTEXT.md`，条件评估方式见 D18，复核后的处理结果见 D23。

### D18 AI 提供条件评估意见，人工确认是否满足

用户在 Q18 中明确：**AI 给意见，人工评估是否满足。**

首版允许 AI 对条件是否满足提出评估意见，并附理由、原文引用与缺失信息。AI 评估建议与人工评估结论分开记录，条件是否满足由本人确认；未经确认的新建议不能直接替换人工评估结论。

对应术语已记入 `CONTEXT.md`，决策见 [ADR 0005](adr/0005-human-confirmed-condition-assessment.md)。下一版 PRD 需调整 G02、M03 与第 10 节的条件评估和确认语义；人工确认的操作与理由要求见 D19，资料不足时的处理见 D20。

### D19 人工确认可复用 AI 评估依据

用户在 Q19 中选择 A：认同 AI 的条件评估意见时，可复用其理由和引用并直接确认；调整或否决其意见时补充本人的理由。

确认记录保留本人选择的结论、确认时间及所用的 AI 建议与材料引用，复用理由仍保留 AI 提出者归属。术语“评估依据”已记入 `CONTEXT.md`；人工确认条件状态不自动表示认同整条论证。

### D20 部分依据下允许明确限定的倾向性意见

用户在 Q20 中选择 A：材料有部分依据但尚不充分时，AI 可以给倾向性意见，明确标明“依据有限”，说明倾向、理由和资料缺口，由本人最终判断。

已有依据、AI 推断和资料缺口分别呈现，未取得的字段保持缺失；倾向性意见仍属于 AI 评估建议，不自动确认条件状态。术语“倾向性意见”已记入 `CONTEXT.md`，人工确认方式沿用 D18 与 D19。

### D21 未核对内容可先收录为个人研究草稿

用户在 Q21 中选择 A：尚未核对的内容允许先复制到个人图谱作为研究草稿，保留“待核对”标记，认同程度由本人另行标注。

收录不自动改变重建核对状态，也不自动标为认同；尚未表达个人立场的内容沿用“待研究”。此规则补充 D04 与 D15，术语“个人研究草稿”已记入 `CONTEXT.md`，并补入 [ADR 0004](adr/0004-review-selected-arguments.md)。

### D22 默认对照复制时的作者版本

用户在 Q22 中选择 A：个人版本默认与复制时的作者版本对照，保留该版本作为对照基线；作者后续观点以差异展示，由本人决定是否合入个人版。

作者更新不自动替换对照基线，也不自动改写个人论证。此规则补充 D03、D06 与 D16，术语“对照基线”已记入 `CONTEXT.md`，并补入 [ADR 0002](adr/0002-preserve-argument-lineage.md)；复核后的处理结果见 D23。

### D23 复核结果明确区分修订、维持与稍后处理

用户在 Q23 中选择 A：审阅影响建议后，明确选择“修订判断”“维持原判断”或“稍后处理”。前两项完成本次复核并保留结果与理由，“稍后处理”保留复核提醒。

完成复核不要求改变原立场，维持原判断也是明确的处理结果；该结果对应本次影响建议，不表示其他未处理建议已完成复核。此规则补充 D16、D17 与 D22，术语“复核结果”已记入 `CONTEXT.md`。

### D24 主张与推导使用四种个人立场

用户在 Q24 中选择 A：主张和推导关系均使用“待研究”“认可”“质疑”“不认可”四种个人立场。“质疑”表示有具体疑问，但尚未明确否定；“不认可”表示目前明确不接受。

收录后未表达立场的内容仍默认“待研究”。个人立场与重建核对状态、条件是否满足及复核结果分别记录；“不认可”不代表原作者没有表达该观点，也不自动删除相关内容。此规则补充 D04 与 D05，相关术语已记入 `CONTEXT.md`，并补入 [ADR 0001](adr/0001-separate-claim-and-inference-stance.md)；下一版 PRD 第 10 节需据此调整个人立场的状态命名。

### D25 共享前提的内容修改默认只影响当前分支

用户在 Q25 中选择 A：同一前提被多条分支共用时，修改其内容默认创建当前分支的局部版本，其他分支保留原前提；也可主动选择统一更新共享前提。

统一更新需先展示引用分支与影响范围，并经本人确认。此选择确认 PRD G03 与 G04 的默认修改范围，局部版本仍保留所依据内容的溯源；对应术语已记入 `CONTEXT.md`，决策见 [ADR 0006](adr/0006-local-edits-to-shared-premises.md)。本决策针对前提内容的修改范围。

### D26 明确区分前提共同依赖与独立支持

用户在 Q26 中选择 A：多个前提指向同一结论时，明确区分“需要共同成立”与“各自独立支持”；原文未说明组合关系时保留不确定性。

前者表示同一步推导依赖一组前提，后者表示各项理由分别提供支持。此区别用于解释缺少某个前提会影响哪一步推导，不将前提成立等同于已证明结论；AI 补充组合关系仍遵循 D07 的推断归属与审阅规则。相关术语已记入 `CONTEXT.md`，决策见 [ADR 0007](adr/0007-explicit-premise-combinations.md)；下一版 PRD 的论证重建、关系模型与影响解释需保留这一结构区别，联合推导的个人立场标注单位见 D27。

### D27 以整步联合推导为个人立场标注单位

用户在 Q27 中选择 A：对“A、B 共同支持 C”的推导，在整步联合推导上标注个人立场；A、B 仍可各自单独标注立场。

因此，可以明确表达“认可两个前提，但质疑它们共同支持该结论的推导”。联合推导使用 D24 的四种个人立场，不因各前提被认可而自动获得认可状态。此规则补充 D05 与 D26，术语“联合推导”已记入 `CONTEXT.md`，并补入 [ADR 0001](adr/0001-separate-claim-and-inference-stance.md) 与 [ADR 0007](adr/0007-explicit-premise-combinations.md)；此决定不规定画布的具体呈现方式。

### D28 历史判断默认回放当时材料与评估记录

用户在 Q28 中选择 A：回看某次已保存的个人判断时，默认展示当时的材料版本与评估记录，后来新增或修订的材料另行对照。

此规则确认 PRD 第 10 节的历史回看原则，与 D22 的作者对照基线分别记录：前者保存某次个人判断的依据，后者用于比较个人论证与其起步的作者论证。后来导入的材料不能仅因原文发布时间较早，就成为本人当次判断的已记录依据；可用当前信息另行审视旧判断，但不改写历史记录。术语“历史判断记录”已记入 `CONTEXT.md`，与“复核结果”“对照基线”分别定义（OD-19 已关闭）；决策见 [ADR 0009](adr/0009-preserve-historical-judgment-context.md)。

### D29 首版采用本机 Web，后续按需增加 Swift 外壳

用户比较本地 Swift App 与本机 Web 后，在 2026-10-01 确认采用本机 Web：首版采用本机 Web，后续按需增加 Swift 外壳。应用在本机运行，材料与图谱在本机保存，并提供简便的启动入口；首版不采用纯原生 Swift 图谱界面。

前述技术起点为 React 与 TypeScript 界面、React Flow 图谱编辑、本地服务、SQLite 与本地材料文件，相关工程方案见 [ADR 0011](adr/0011-frontend-stack-and-canvas-engine.md) 与 [ADR 0015](adr/0015-deployment-backup-and-retention.md)。主张、联合推导、证据与历史判断保留独立领域模型，不将画布状态作为完整研究资产；本题不锁定具体依赖版本或模型供应商。材料外传范围已另行确认：允许送审明确提供零数据留存（ZDR）与企业条款、承诺不将输入用于训练的供应商，详见 [ADR 0014](adr/0014-model-provider-and-extraction-strategy.md)。

### D50 拖放卡片建立下一步推导，支持多个子推理节点

### D112 派生陈述不自动复制上游推导，按需另建独立推导

### D113 每项推导只承载一个结论，多个结论分别建立推导

2026-10-08，第一性原理对象访谈第十二问以“收入增加、总成本不变”分别用于推出“利润增加”和“利润率提高”为例，比较一项推导连接多个结论与分别建立推导。用户选择 B：每项推导只有一个结论，多项推导可以共享原有前提，分别维护说明与个人立场。

一项推导连接一个或一组前提与恰好一项结论陈述。相同前提用于不同结论时，分别建立具有独立身份的推导；共享前提通过引用已有陈述实现，不因结论数增加而复制前提对象。不同推导可以分别编辑理由、调整引用或表达立场，操作其中一步不改写另一项推导的理由或立场；对结论陈述的个人立场仍独立记录。

该规则与 D105、D106 一起确定推导边界：同一结论的不同理由分别形成推导，必须共同配合的前提属于同一步推导，而每一步只对应一个结论。画布可使用分别可操作的连接与推导标签，不要求新增独立推导卡片。

### D114 条件作为独立规则对象，可被多项陈述或推导引用

### D115 每次条件评估具有独立身份，绑定当时规则、材料与时点

条件负责定义“怎样判断”，条件评估负责记录“这次依据什么、由谁、在何时得出什么结果”。同一规则可以对应多次评估；新材料下形成的新评估不覆盖旧评估的结果和依据，旧记录仍回到当时的规则版本与材料版本。结果相同也不能仅凭结果值把不同依据下的评估视为同一条记录；任务重试与重复请求的幂等策略另行设计。

### D116 修改阈值保存后，使用齐全且可比的本地输入自动重算

### D117 阈值规则保存与重算分别处理，计算失败不撤回已保存修改

2026-10-08，第一性原理对象访谈第十六问比较阈值保存与自动重算必须一起成功，以及保存成功后允许计算单独失败和重试。用户选择 B：保留已保存的新规则，计算失败时显示失败状态并允许单独重试。

### D118 授权 auto-select，按确定性工具与 Agent 分工推进后端实现

2026-10-08，用户明确授权“auto-select 模式”，由代理自主选择常规最优决策，以完整实现需求和架构、代码健壮性为目标，取代逐题等待 A/B 的协作方式。后续自动选择须明确记录依据与取舍，不能伪称每项均由用户逐项选择；技术验证、真实外部服务验证与本人研究验收分别记录。

按此授权自动采用 Q17 的 A：明确且受支持的结构化标准由确定性工具执行；开放性判断由 Agent 提出有出处、理由和缺口的评估；混合标准结合两者。Condition 保存判定要求，ConditionEvaluation 保存有版本与依据的结果，执行能力独立装配。内部模型仍遵守 ADR 0014 的无外发、交易或任意文件写入工具约束，工具计算与候选入库由受控应用流程编排；外部 Agent 通过 MCP 使用同一业务接口。

自动确定后续触发规则：D116 的本地确定性重算在规则保存后自动触发；定性与混合条件先保存，只有本人明确发起评估或已授权 Agent 显式请求任务时才运行模型。材料更新仅产生待复核信息或候选，不静默覆盖判断。旧规则下的人工确认保留为历史，当前规则未确认时明确显示待本人确认，不把旧确认冒充当前规则结果。

本次后端实施包含已确认但原排期待定的 MCP 共用操作接口与独立公开数据源核心；开源发布和第三方兼容性仍须有实际证据。架构不增加远程访问、多人协作、定时抓取、交易或跨项目数据外传。常规实现可自主推进，供应商账户条款、秘密凭据、实际材料内容和用户的研究判断不能由 auto-select 编造。

### D119 后端采用原子业务批次、版本化对象与独立评估任务

2026-10-08，依据 D118 的 auto-select 授权确定后端施工契约，详见 ADR 0017。一个显式业务批次中的陈述、推导、条件引用及证据关联要么全部成功，要么全部不写入；请求列出已读相关对象版本，新建对象可以在同一批次引用。不同理由即使端点相同也不按端点去重。幂等键绑定调用主体、项目与请求内容，相同键不同内容返回冲突。

### D136 后端批次操作的统一撤销与重做

2026-10-09，依据 D118 的 auto-select 授权接通后端与原画布的操作历史。沿用 D65 每项目最近 40 步的产品要求：一次业务批次及其连带对象、相关布局作为一步；画布一次拖动、绘图或样式提交作为一步。无变化保存、点选、视口与未提交输入不占历史。撤销后发生新的实际研究编辑会清除重做分支，材料导入不单独占用研究编辑步骤，也不随撤销删除。来源、来源版本和原文件继续保留。

撤销通过受版本保护的新事务恢复该动作之前的对象内容、参与状态、立场、条件/节点及相关布局。对象写入版本、项目修订和历史游标版本递增；恢复原内容版本身份，使旧证据、条件评估及验证节点重新按原内容判断适用性。不可变编辑审计及任务执行记录不回退、不删除，历史判断也保持原来固定版本。撤销不重新调用模型或自动重算；后台评估结果当前作为独立历史步骤保留。

客户端传入已读取的项目修订、布局版本和操作历史版本，服务端使用自己保存的版本引用恢复，不接受任意替换对象。三者有并发变化即明确拒绝；同一操作键重试返回原结果，不再撤销另一步。Agent 凭据可读取操作历史，但不能通过撤销恢复或改变本人判断，执行仍须本人会话。普通写入与撤销都返回完整变化集合；工作区和同步返回下一步动作名称。原画布按钮和快捷键共用同一队列，先完成手头画布提交，再执行撤销。
