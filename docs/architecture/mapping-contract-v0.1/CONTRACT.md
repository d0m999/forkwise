## 1. 身份、所有权和生命周期

- Project 是隔离与历史的单位。所有对象归属一个 Project，不能用另一个项目的 ID 绑定；跨项目复制另建身份。
- Thought 对应本契约中的普通卡片身份，独立保存纯文字 title，恰好拥有一个 Body、一个 CanvasItem。title 不是 Body 的首个 heading；Body 可为空。Body 不可被两个节点共享；当前一正文一摆放仍是第6节所述的保守提案。移位、改文、撤销均保留卡片身份。
- Body 是有序 Block 列表。Block 有稳定 ID；重排保留 ID，复制生成新 ID，删除再撤销恢复原 ID。普通文本、标题、列表、图片、附件、引用等是呈现结构，不强制观点或假设分类。参考实现实现 text/heading/listItem/asset/reference/opaque 联合类型；只有 listItem 可形成块内父子，未知内容用 opaque 原样保留。
- CanvasItem 表达可定位的画布身份，以 kind 区分 Thought、Shape、Text、Image、Stroke、Group、Frame；MaterialCard 保留为提案类型。各 kind 通过独立内容记录承载自己的能力，不把形状、文字、图片包装成带写字板的 Thought。Pose 保存位置、尺寸与允许的旋转，独立版本化；StackOrder 保存 D310 四类内容对象的共同持久顺序。正文写入不得覆盖 Pose 或 StackOrder，拖动不得覆盖正文。
- Material 是项目中可复用的资料身份，拥有可变 source 元数据与不可变 MaterialVersion。MaterialCard 是本包仅用于解释资料摆放的产品建议，不是已确认的新 UX 类型。每个建议中的 MaterialCard 捕获一个具体 MaterialVersion；更新 source 不悄悄改变已有卡片，更新快照必须显式执行。重复使用同一资料产生新卡片，重复复制 Thought 产生新 Thought/Body/Block，已有 Asset 可复用。
- Asset 是不可变内容身份及媒体元数据，不是独立图片的画布身份。不同文件字节使用新 Asset；这不提供“替换图片”操作，D382 永久排除该入口，独立图片更新内容须删除旧对象再添加新对象。删除节点不立即删除 Asset；只有所有当前与保留历史引用都释放后才具备回收资格，本包不执行物理回收。
- Reference 是正文内指向 Thought 或特定 MaterialVersion 的引用，不等于屏幕连线。引用身份在本参考模型中就是其来源 Block ID；目标删除变为 broken，保留可解释的目标身份，不级联删除正文。
- Connector 是用户画出的普通连线，可有用户文字标签 label，与卡片的 Tag 不同。不自动解释因果、支持、反对、出处或推理。允许环；禁止两端绑定同一个对象。端点可绑定同项目的 Thought、Shape、Text、Image、Group、Frame 对应 CanvasItem，或是世界坐标 free point；Stroke、其他 Connector 及未采纳的 MaterialCard 不自动成为绑定目标（D418、D419）。
- Group 是一层集合，只含普通 CanvasItem，不含 Group/Frame；Frame 是单父、无环空间容器，可含 Frame。两者不等于 Reference/Connector。每个 item 至多一个直接父容器，类型为 group 或 frame。
- 删除 Thought：墓碑 Thought/Body/CanvasItem 及其 Pose、归属和 CardTags，移除 StackOrder 中对应项；指向它的 Reference 标 broken；与该普通 CanvasItem 相连的 Connector 一并删除，项目 Tag 保留。仅保留内容的容器移除才将容器绑定端点按删除前世界坐标冻结为 free point。删除 Frame 或取消 Group：保留内容与世界坐标；直接成员提升到画布顶层，子 Frame 保留自身成员。删除整个 Group 则删除组及成员。删除 Material source：保留已有快照卡片与引用，阻止新增复用。历史保留可恢复对象，不复用被删 ID。

### 1.1 卡片标题、项目标签与检索

- title 保留用户原文与手动换行；空值由界面显示“未命名卡片”，占位不写入内容或搜索索引。标题保存使用 thought 写域，正文使用 body 写域；D262 的一轮标题编辑、D263 的新卡创建与首次标题输入各按既定动作边界撤销，不并入后续正文或标签操作。
- Tag 是项目级稳定身份，保存 name、color 和删除状态；nameKey 仅为名称派生的判重索引，不接受独立写入。当前有效标签名称判重忽略大小写，显示保留用户写法（D193、D194）；不借用全文搜索的简繁转换自动合并标签。创建同名标签复用已有身份，重命名撞名拒绝且不合并。默认中性色；改名、改色只更新项目标签记录，所有引用它的卡片同步读取（D185–D187、D192）。
- CardTags 是每张卡片独立的 orderedTagIds，按添加顺序排列、不得重复或引用其他项目标签。拖动排序只修改该卡的关联；卡片上的一行摘要和写字板均读取该顺序，搜索使用完整集合（D167、D195）。卡片复制保留标签及顺序、独立保存关联；跨项目粘贴先复用目标项目同名标签及其颜色，缺失时新建，再改写为目标项目标签 ID（D327、D347、D348）。
- 删除项目标签需先确认受影响卡片数量；命令原子墓碑标签并移除全部当前卡片关联，一次撤销恢复原身份、名称、颜色和关联顺序。不能用删除卡片或正文实现移除标签。若确认后受影响范围变化，重新读取并确认，不能悄悄扩大删除范围（D188、D189）。
- 当前及历史搜索条件引用 tagId，不把标签名保存成关键词。改名后显示新名称；删除后由保留的标签身份/末次名称显示“已删除”，查询进入条件失效状态，直到用户移除该条件；新选择器不提供墓碑标签。撤销标签删除使旧引用重新有效，不重写原关键词（D190–D192）。
- 搜索投影只覆盖当前项目的现有普通卡片：从独立 title、完整 Body 的可检索文字及完整标签关联生成，采用既定关键词匹配与标签交集规则。卡片预览截断、折叠和标签显示数量不裁减索引；标题与正文分开保留命中位置，内容最近编辑时间从标题/正文实际修改派生，布局及临时阅读不推进该时间。独立文字、形状、图片不因此加入卡片搜索，来源区、附件原件与图片 OCR 仍排除（D174、D238、D245、D283、D421）。

### 1.2 独立对象的内容与绑定

| CanvasItem kind | 独立权威内容 | 必须保留的产品边界 |
| --- | --- | --- |
| Thought | title、Body、CardTags | 标准卡片；完整写字板只属于此类，不从正文首行猜标题 |
| Shape | shapeType、短文字、填充/轮廓等外观 | 矩形、圆角矩形、椭圆、菱形、三角形；没有完整 Body，不提供转卡（D402、D404、D422） |
| Text | 有序文字 runs 及局部强调 marks、对象统一字号、行距、整块对齐、宽度模式 | 无完整 Body、无内嵌图片；局部颜色/加粗可不同，局部字号不允许。左右调宽保持字号，四角缩放同时更新字号与 Pose，一次撤销（D383–D401） |
| Image | 固定 assetId、相对原图的 crop；显示尺寸/旋转在 Pose | 独立图片无标题/卡片框；原图保留，裁剪非破坏，支持拉伸与90°旋转，永久无替换图片（D355、D363–D382） |
| Stroke | 普通笔/荧光笔种类、笔迹路径、颜色/粗细/透明度 | 独立笔迹，不修改下方文字或原图；撤销/选中删除，无橡皮，不作为连线端点（D405、D406、D418） |
| Group / Frame | 容器身份与既定归属；Frame 名称/外观 | 不附加完整 Body，成员仍保留自己的内容记录；沿用 D414、D416、D420 |

同一种图片资源可被正文图片块和独立 Image 引用，但两个使用位置的尺寸、裁剪及对象身份不共享。Image 的 assetId 在该对象生命周期内固定；副本可复用同项目不可变 Asset，自己的 crop、Pose 独立。跨项目复制建立目标项目内的资源身份/引用，不能直接绑定源项目 ID。取消裁剪丢弃预览；应用/恢复裁剪时 crop、受影响 Pose 与附着图片必要的 Attachment.offset 同一事务保存，大图查看器缩放、平移和“查看原图”状态不持久化（D367–D381）。

独立 Text 结束编辑时若只有空白则移除该对象；空卡片仍保留（D254、D390）。创建与连续首次输入按 D394 合为一步；不把文字内容和字号留在渲染器的私有记录中。各独立对象删除时，其内容、Pose、归属、持久顺序及应删除的相连线在同一动作中处理；撤销恢复原对象身份及完整外观，不物理删除被历史引用的 Asset。

### 1.3 持久叠放与临时显示

StackOrder 是项目内 Thought、Shape、Text、Image 的共同有序集合，按从后到前保存对应 itemId；每个有效对象恰好出现一次，无重复、墓碑或跨项目 ID。不按类型另排，也不从创建时间、type/id 分页顺序或当前 DOM 顺序推断（D310）。容器归属与持久顺序分别保存，移动、入组、解组和分区归属改变不擅自重排成员。

- 新建四类对象追加到最前；复制的一批对象追加到最前，内部采用原持久顺序，不采用点击顺序（D322、D323）。删除移除对应排序项，撤销同一次动作恢复其原顺序。
- 提供置顶、前移一层、后移一层、置底。逐层操作跨过该方向最近的未选重叠对象，跳过无重叠对象；多选保持内部顺序，有冲突时允许必要的已选对象同向联动。所有目标基于同一操作前状态计算并一次提交，不能逐个改序让后一个对象读到前一个对象的中间结果（D313–D319）。
- StackOrder 独立版本化；修改顺序不更新正文、位置或尺寸。没有可执行变化时不写版本或历史，菜单保留且置灰，不附加原因提示（D320、D321）。同排序域的并发修改需版本校验，但不阻塞无关联正文保存。
- 单卡或纯卡片多选临时置前只属于 UI 选择状态，内部沿用持久顺序；混合多选及非卡片选中保持实际遮挡。取消选择恢复持久层级，保留内容、尺寸、位置修改。明确置底/逐层调整后立即显示实际结果，本次选择暂停临时置前（D303–D305、D309、D311、D312、D315）。临时状态不写 StackOrder、不进撤销或 Agent 的权威空间数据。

本次共同排序映射覆盖 D310 明定的四类内容对象。笔迹、Connector、Group/Frame 外框与这些内容之间的具体绘制层适配仍须按各自既定规则核对，不借新增排序字段擅自扩大层级菜单或赋予固定类型优先级；分区背景不得遮住成员正文（D416）。

### 1.4 随动批注附着（待实现映射）

D421 明确保留 D78/D84：自由文字、形状、图片或手绘批注明确附着后跟随目标，复制为自由副本，删除目标保留批注并解绑。Attachment 是独立附着关系，不是卡片 Tag、Body Reference、普通 Connector 或容器归属；附着不改变批注的 kind、内容身份或研究语义。

- 每个批注至多一个有效附着目标，保存同项目的目标身份和相对偏移；当前卡片目标映射到 Thought 的 itemId，旧整步推导目标由显式 Adapter 保留其原身份与锚点。不能把普通 Connector 当成旧推导，也不据此新增对任意对象/组/分区的附着入口；旧目标和新笔迹类型的适配仍待验证。
- 附着期间世界位置从同快照下的目标锚点与偏移派生，尺寸/允许旋转仍属于批注 Pose；目标移动、增高或既有投影变化更新空间显示。拖动批注修改相对偏移，不另存一份可独立写入的绝对位置。解除附着时将当时世界位置写回自由 Pose，与关系移除原子提交。
- 附着图片应用裁剪保持完成时的世界框，恢复完整图按当前显示变换展开，保留已可见内容的位置/比例。由新可见框按原锚点定义回算 offset，并与 crop/尺寸等变化原子保存，不能用写派生 Pose.x/y 代替。expected 校验图片、附着状态与目标锚点依赖，冲突无部分写；offset 未变只作为读依赖，不新建附着版本。预览/取消不落盘，一次应用/恢复的 undo/redo 同时恢复内容、几何和必要偏移；完整闭包见[字段映射](docs/STORAGE-MAPPING.md#附着图片裁剪与恢复的原子闭包待实现)，仍待实现验证。
- 附着与容器移动分别处理，沿 D78 明确处理原框架内批注，避免双重随动；混合组合与新类型的具体适配不在此补成新产品决定。附着/解除/重新附着及完成的偏移调整各按已有一次动作边界进入统一历史。
- 删除目标先计算删除前世界位置，原子解除指向它的 Attachment 并保存未被本次删除范围包含的批注自由 Pose；这些批注、内容与适用的 StackOrder 项保留。批注自身同时明确选中删除或按既定整组删除规则纳入范围时，仍删除其内容和附着。撤销同一动作恢复原身份、附着和偏移，不创建新批注；批注附着与相连 Connector 各走自己的生命周期。
- 复制批注读取复制时的世界位置与内容，副本为自由对象、不继承附着；同时复制目标也不自动重建该关系。跨项目同样不把源项目目标 ID 写入副本。Frontend/Agent 读取附着身份和空间投影须使用同一快照，无法解析的旧目标保留缺口，不猜测替代目标。

## 2. 权威写入与版本

唯一写入 seam 是 Mapping.execute(command, actor)。UI 和 Agent 均调用它；存储 Adapter 承担原子提交。actor 是可信会话上下文，绝不采信 command 内自称 human 的字段。read(query) 和 observe(cursor) 是其余两个 Interface；后两者只读。客户端草稿不是另一个权威库。

command = {commandId, type, expected, payload}。commandId 在项目内唯一；expected 按写域给出不可变版本 ID（新对象使用 null）。thought（含标题）、body、tag、cardTags、各独立对象内容、pose、attachment、stack、material、connector、containment 分域，互不借用全局 revision 做乐观锁。跨域操作一次原子校验所有修改域及用于计算本次影响范围的依赖版本，失败完全不写。完整字段与操作闭包见[字段映射](docs/STORAGE-MAPPING.md)。这些新增域尚未接入参考模型。

处理顺序：认证及项目权限 → 严格解析 → 查 commandId → 已成功且规范化请求相同则返回原 receipt → 同 ID 不同请求报 IDEMPOTENCY_MISMATCH → 校验域版本及约束 → 原子持久化实体/版本/历史/receipt/changefeed。丢失 ACK 后原请求可跨重启重试，不能因旧 expected 拒绝已完成命令。失败命令不消耗 commandId。幂等保留窗口不得短于客户端可重试窗口；本参考模型不清理 receipt。

每次成功写入生成新的不可变 VersionId；project revision 和域 generation 单调增长。撤销是新写入与新版本，不把时钟或版本 ID 倒退。Project revision 用于读一致性与变更游标，不是所有命令的写锁。并发编辑同一正文冲突返回当前版本，由调用方重读/人工合并；不虚构自动合并。

## 3. 历史与编辑批次

人类可按项目时间顺序撤销/重做；Agent 可读历史，不可执行 undo/redo。项目历史包含 UI 和 Agent 成功写入，因此人类可以撤销 Agent 的最新变更。参考模型保留 40 个可撤销 action；保留的不可变版本不等同于可撤销 action。新的研究编辑清空 redo 栈；非研究步骤的资料/资源导入保留 redo 栈。undo/redo 自身产生新 change revision，但不插入可无限递归撤销的普通 action。

D283 的 1 秒连续编辑间隔、400ms debounce、2s 最大等待及 IME 单元须由 UI 草稿协调器贯彻：编辑组以节点/会话/焦点/1s间隔分界；组内多次落盘合并成一个 undo 单元，仍保留独立写入版本；拖动或其它命令会截断正文编辑组，禁止跨并发事件重排历史。composition 未结束不拆分提交；2s 上限在 IME 完成后生效。ACK 仅确认其覆盖的 draft generation，旧 ACK 不能清除新草稿。参考模型分别实现服务器历史组和最小草稿状态机，实际编辑器/网络接线仍待生产集成。

## 4. 两个投影，同一真相

Frontend read：按卡片标题与完整标签关联、各 kind 的内容、Attachment及目标锚点、世界坐标、持久顺序、结构化 Block、连线端点、frame/group 布局重建画布；相关域版本可见，临时选择显示最后由 UI 叠加。Agent read：优先 identity index（身份、类型、卡片标题/标签 ID 与版本）→ 局部正文/独立对象内容/批注附着/邻接/资料快照 → 必要时分块展开，避免把画布截图当唯一结构。不得把空间邻近、标签、附着或前后层级自动变成语义关系。新增投影字段的实现状态同第7节。

read 固定 project revision，返回 snapshot token。后续页面只能读取该 token 的相同快照；过期必须 SNAPSHOT_EXPIRED，不能用当前数据续旧页。身份索引稳定排序按 type/id，页边界不改变 ID；该分页顺序不代表画布遮挡，StackOrder 以同快照下的原序与序位返回，必要时单独分页。token 是不透明快照引用，不是授权；每次读仍检查权限。带预算读明确返回 coverage、totalItems、nextCursor、fidelity；不枚举无限长 omittedIds；正文截断必须说明，不得把未读内容写进摘要。参考模型用 UTF-8 字节预算替代模型 tokenizer，明确 budgetUnit，不能称 token 数。

observe(afterRevision) 返回顺序 delta：变化对象/写域和被删除 ID；游标太旧返回 RESET_REQUIRED。UI 与 Agent 根据相同 delta 作缓存失效，再用相同 revision/token 重读；不能拼接不同 revision 页后声称完整图。摘要只基于本次返回事实，包含 coverage；本包不调用 LLM，不生成推断性摘要。

## 5. 适配旧系统与未决产品项

目标 Adapter 对照旧 entities/versions/links/layouts/action_history 和 GraphWriteService，不照搬它们的模糊术语。R2 的 localStorage 文本+pose混合记录只能做草稿/缓存，不能直升权威库。上线前须确定 ID 映射、旧引用缺失策略、事务持久化、真实权限和迁移回滚。

建议已固定为本包测试前提：一节点一正文一摆放；资料快照引用；项目全体行动按时间撤销；frame 使用世界坐标规范化。真正需产品确认：资料原始文件永久删除/保留策略；跨项目资料共享是否要成为产品能力；超过40行动后的历史展示保留期。它们不阻塞本包，但不得以本包存在为由擅自上线。

## 8. 版本保留与规模边界

不可变版本是逻辑不变量，不等于无限保留承诺。此参考Adapter不清理archive、receipts、changefeed；读snapshot在内存复制整份状态，写入也序列化完整JSON。随着项目增长会增加内存与存储占用，不能据此宣称可扩展架构。生产需单独决定历史版本/快照/幂等窗口、压缩与回收，不能先删仍被引用的Asset或MaterialVersion。Agent投影是派生查询/缓存，永远不形成第二份可写权威。

编辑组由可信客户端输入协调器按D283产生；服务器只合并同actor、同body、同editGroup的相邻正文提交，不用两次网络提交间隔替代输入间隔。因此2秒自动保存批次不会把持续输入的同一动作切碎；其它命令会截断合并。跨会话editGroup须使用session唯一前缀，避免重启复用。

## 9. 生产语言与 CRDT 策略（2026-10-12 补充）

生产推荐沿用 TypeScript 前端/领域/后端、现有 Node.js 与 SQLite 事务；本包 Python 只是参考验证实现，本次未迁移。当前不采用 CRDT：Agent 投影和 Body/Pose 分域不以它为前提。若以后证实频繁的人与 Agent 同正文并发、离线多设备或多人实时协作需求，再经独立批准对 Body/Block 做局部试验。

CRDT 收敛不保证改写语义正确；Agent 应提交细粒度补丁，不能以可合并为理由用旧基线整段覆盖。权限、领域不变量、业务幂等和同revision投影仍要保留；CRDT 更新与 SQL 派生投影须有一致、可恢复的持久化协议。元数据、日志、GC与离线恢复均有存储和工程成本。

继续采用人类执行的项目时间顺序undo/redo，包含Agent修改；不改为按actor选择性撤销。Rust/WASM只在实测热点或必要集成证明有价值时考虑，不是CRDT必选项。Yjs（JavaScript）、Yrs（Rust）与Automerge（Rust核心及JavaScript绑定）的候选事实和条件试验验收见 [ADR 0004](docs/adr/0004-language-and-crdt-strategy.md)。本次仅记录建议，未安装、采用或性能测试任何CRDT库。
