状态：施工中；日期：2026-10-24。本文记录 #26 当前生产接口补充，测试与验收状态仍以施工记录为准，不覆盖参考合同的历史状态。

## 批量卡片布局回执

`Receipt.cardPoseVersions?: Record<string, string>` 是 `pose.batch` 成功回执的可选增量。

- `payload.poses[].id` 和 `expected` 的键使用 `Card.id`；`cardPoseVersions` 的键使用该卡片的 `CanvasItem.id`。两种身份不能混用。
- 值为本次命令实际提交的新 `item.versionId`。Mapping 在同一 SQLite 事务中从实际 `cardChanges` 构造映射，与原 receipt、change 和历史一同提交；不另行读取最新卡片。
- 只列实际变化的卡片。无变化成员不列入；整个命令无变化时沿用原无变化回执，不合成映射。
- 既有 `versions` 字段继续描述首个实际变化卡片，语义与值保持。其它命令不新增此映射。
- 历史持久回执原样重试，不回填该字段；旧回执缺少此字段不表示其保存失败。

## 保存确认与待执行删除

批量布局保存 owner 在原 `execute` 成功后、刷新投影前，将原命令与原回执同步通知待执行删除意图。

删除意图捕获原项目、`Card.id`、`CanvasItem.id`、各域版本与关联线闭包。只在同项目、同 `commandId`、目标为唯一批量成员且其原 `expected` 布局版本符合捕获链时，检查该目标的确认。

- 目标 `CanvasItem.id` 未出现在 `changedIds` 时，其布局版本不推进。
- 目标实际变化时，只采用 `cardPoseVersions` 中该 `CanvasItem.id` 的自身新版本；不用首卡的 `versions.pose`，不采用其它成员的版本。
- 实际变化目标缺少自身映射或身份、版本链不符时，只取消当前待执行删除，要求用户重新明确操作。已成功保存的布局继续完成确认，不抛异常令 owner 重发。
- 重复确认、无变化确认及删除命令定稿后的确认不推进版本。原关联线闭包、正文、标题、外观与标签版本均保持各自既有边界。
- 删除命令仍在既有保存队列排空后定稿；未知 ACK 重试保留原命令及其 JSON，不因刷新投影而重新选取删除依据。
