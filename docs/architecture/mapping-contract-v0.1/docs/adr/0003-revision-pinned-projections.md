# ADR 0003：同revision投影与有预算的逐层读取
状态：工程采纳（参考实现）

## 背景
截屏与自然语言摘要无法稳定寻址节点；分页跨写入会混合事实；固定token预算与无限全图承诺互相冲突。

## 决定
权威存储一份，Frontend和Agent共享identity/version拓扑。正文与资料detail按固定snapshot无损JSON片段展开。observe返回同revision token，防止delta读取竞争。整个响应UTF-8字节计预算；超长不可拆结构项明确失败。summary默认null；不推断用户连线含义。

2026-10-12 评审补充（待实现）：投影需包含卡片独立标题、完整标签关联及同快照的名称/颜色、独立对象内容类型，以及四类内容的持久顺序。身份索引的 type/id 排页顺序不能替代 StackOrder；排序单独分页也须使用同一快照和原序位。临时选中置前只存在于 Frontend UI，不进入 Agent 的权威空间投影。搜索索引从完整标题/正文/标签派生，不从有限卡片预览或渲染器私有状态重建；具体范围仍按 D245/D421，仅搜索普通卡片。此补充不追加参考模型通过项。

随动批注读取包含同快照 Attachment、目标锚点与自身尺寸，世界位置派生而非另一份可写姿态；未知旧目标明确缺口。目标与偏移跨快照拼接不能声称已正确恢复附着，新增读取待验证。

附着图片裁剪/恢复后的读取还须将同次 crop、尺寸/方向及必要 offset 变化作为一个 revision 重建；不能显示新裁剪配旧偏移。恢复以当前已应用的图像变换为依据，不读取裁剪前旧布局来覆盖用户后续移动/拉伸。具体闭包见[字段映射](../STORAGE-MAPPING.md#附着图片裁剪与恢复的原子闭包待实现)，本次仍仅文档要求。

## 替代方案
每次返回全图最简单，但大正文不可控；仅Markdown摘要便宜却丢ID与拓扑；每页取最新数据无需快照但无法称一致结果。

## 后果
Agent可以先选择局部再取细节，代价是调用方维护快照/分页和组装。生产要定义snapshot TTL、授权变更、changefeed保留与背压；参考模型snapshot仅在内存中，重启即明确过期。未测性能与模型token消耗。
