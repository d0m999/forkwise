# ADR 0004：生产语言与 CRDT 引入策略

日期：2026-10-12
状态：按用户要求记录的工程建议；不是 CRDT 采用、代码迁移或生产集成授权

## 背景

本包用 Python 标准库验证领域契约，便于独立运行；它不是将生产技术栈改为 Python 的选择。现有后端已有 TypeScript/Node.js、SQLite 事务和 GraphWriteService。需要把语言选择、同步算法选择与领域语义分开，避免因 Agent 视图或正文/姿态分域而过早引入分布式编辑复杂度。

## 决定

1. 生产推荐沿用 TypeScript：前端、领域命令与后端共享类型和运行时契约，后端继续采用现有 Node.js 栈及 SQLite 原子事务。Python 仅保留为本包参考实现和可移植验收样例。本次不改写代码。
2. 当前不采用 CRDT。正文/姿态独立版本、统一命令入口、幂等和固定 revision 投影已经解决不同写域的并发及 Agent 读取问题；它们不要求 CRDT。
3. 只有出现可验证的需求，例如人和 Agent 频繁并发修改同一正文、离线多设备同步或多人实时协作，才考虑限定在 Body/Block 编辑的局部试验。资料身份、容器归属、连线删除、权限和项目历史仍由统一领域命令约束；不把整张图自动转换成 CRDT。
4. Rust/WASM 仅作为经测量证实的热点优化或必要集成选择，不是采用 CRDT 的前置条件。Yjs 是 JavaScript 方案；Yrs 是 Rust 的 Yjs 协议实现，并提供 WASM/JavaScript 接口；Automerge 有 Rust 核心及 JavaScript 绑定。按契约兼容性、编辑器集成、恢复行为、存储成本和代表性测试选型，不以语言推断速度。

## 必须保留的语义

- 收敛不等于语义正确。各副本得到同一段文字，并不保证用户想保留的判断、段落或改写被正确保留；这属于本项目的语义判断，不能从 CRDT 的收敛性质推出。
- 正文编辑应使用稳定 Block ID 和细粒度操作。把 Agent 基于旧正文生成的整段重写，直接转换成删除全部再插入，仍可能破坏人的新编辑；需要显式补丁、范围/版本校验和必要的冲突审阅。
- 权限、身份所有权、单父无环、普通删除优先、commandId 幂等及项目隔离不因底层更新可合并而消失。更新级幂等不等于业务命令只执行一次。
- 保持现有“项目时间顺序、人类执行、包含 Agent 修改”的统一 undo/redo。不得直接用按 actor/origin 筛选的库级撤销替代项目撤销，也不能让一次快捷键同时触发正文与画布两套历史。库级能力必须先证明能符合项目动作分组及交错顺序。
- 若试验正文 CRDT，必须明确同一逻辑状态的权威持久表示；SQL 查询投影是可重建派生状态，不能与 CRDT 各自接受独立权威写入。更新、业务 receipt、history 和投影检查点需要原子提交，或有经故障测试验证的可恢复协议；不能一边成功就回复“已保存”。
- CRDT 元数据、更新日志和删除历史存在存储成本。须测量压缩、检查点、GC、离线设备重新同步及撤销保留的相互影响；不得先删除仍为恢复、历史或未同步设备所需的信息。

## 候选事实与一手来源

- [Yjs Document Updates](https://docs.yjs.dev/api/document-updates)：更新支持可交换、可结合和幂等应用；更新合并本身不完成删除内容的 GC。这是协议能力说明，不是本项目已经验证的恢复方案。
- [Yjs UndoManager](https://docs.yjs.dev/api/undo-manager)：提供选择性撤销及 origin 过滤。这与本项目统一按时间撤销存在适配工作，不可默认等价。
- [Yrs 仓库](https://github.com/y-crdt/y-crdt)：说明 Rust 核心、Yjs 行为/二进制协议兼容目标及 WASM/JavaScript 接口。兼容目标不代替选定版本的实测。
- [Automerge 仓库](https://github.com/automerge/automerge)：提供 Rust 核心和面向 JavaScript 的接口。列为候选，不表示优于 Yjs 或已经选定。

以上来源于2026-10-12核查；未安装、运行或基准测试这些库。

## 替代方案与取舍

- 全量改为 Rust：增加跨语言、构建、绑定与人员维护成本，当前无实测热点支持。
- 现在把整图改为 CRDT：提前引入离线身份、结构约束与历史适配成本，而现有需求的主要矛盾仍是权威映射与领域规则。
- 永不使用 CRDT：可能在同正文高并发或离线协作成立后限制体验，因此保留有限试验入口。
- Python 直接成为生产主栈：混淆参考验证与既有工程选型，本轮不采用该推断。

## 有条件试验的通过标准（尚未执行）

仅当需求触发、另行批准试验时：固定候选版本，用同一数据集比较字符插入/删除、块移动、富文本/未知块保留、Agent 旧基线补丁、乱序/重复更新、离线重连和权限撤销；验证人类项目级 undo 可按顺序撤销人和 Agent 的交错修改；故障注入覆盖更新已存但 SQL 投影未完成、重启重放和 GC 后恢复。测量大正文延迟、内存、更新/检查点大小及长期存储增长；先定义可接受指标，再决定是否采用。未通过则继续版本冲突与显式合并方案。

## 后果

当前语言推荐明确，参考实现保持可运行；不会因 Agent 需要结构化投影而引入 CRDT。未来试验有清晰范围和退出条件，并保持既有产品建议、领域不变量及40步项目撤销规则。
